# 開発手順

## 1. ローカル起動

[README](../README.md)の手順でNode.js 24.xとGitを用意し、`npm start`で起動する。外部依存はなく、DBや環境変数の秘密情報は不要。

## 2. 初期試作の確認

```sh
npm test
npm run check
```

`node --test`で、実働時間、未入力・不正数量、修正の置き換え、勤務重複、単位別数量、月別集計、未確定の金額、ローカルサーバーの配信範囲を確認する。

ブラウザでは次を確認する。

1. 空の画面で「架空サンプル2件を読み込む」。全画面に試作の説明が見えること。
2. 2026年11月の出勤簿：社員Aは8時間、社員Bは7時間。
3. 給与資料：それぞれ出勤1日、支給額は「要確認」。0円や仮の給与額を出さないこと。
4. 運行管理：社員Aのサンプル車両A・木くず3m³を表示。
5. 処分費：現場A／処分場A／木くず／m³の数量3、金額は「要確認」。
6. 燃料管理：車両Aは25L、重機Aは18L。給油明細と一致すること。
7. 日報Aを修正し、運搬数量を5m³・給油量を30Lにして反映。日報総数が増えず処分費・燃料管理が新しい値になること。
8. 月を2026年12月にすると記録なし。空欄に戻すと全期間を表示。
9. 空欄や0以下の数量、不正な時刻、同じ社員の重なる勤務を止めること。
10. 幅390px程度でフォームが1列、横に長い表だけが横スクロールできること。実iPhoneのSafari確認は別途必要。
11. 再読み込みではタブ内データが消えること。ブラウザによっては終了前の確認が出る。

## 3. 実用版へ進める順序

| 段階 | 作業 | 前提 | 完了条件 |
| --- | --- | --- | --- |
| A | 認証・権限・保存方式の決定 | Q01〜Q04、Q11、Q14 | 設計判断と費用・運用担当を記録 |
| B | 社員・現場・車両等のマスタ、日報の共有保存 | A、Q05・Q06・Q12 | 本人／権限者のみ操作、複数端末で一致、再読込後も残る、二重送信・競合を検証 |
| C | 日報の提出・確認・差戻し・履歴・勤怠 | B、Q04〜Q06 | 修正追跡、日またぎ／休暇等を決定仕様どおり処理 |
| D | 給与資料の確定、必要なら給与額計算 | C、Q07・Q08 | 既存の給与資料との照合、期間・丸め・締め後修正を検証 |
| E | 運行・処分単価・燃料の実運用対応 | B、Q09・Q10 | 単位・適用日・税・計量根拠の照合、マスタ変更でも過去記録が壊れない |
| F | Excel／PDF出力・移行・運用開始 | C〜E、Q11〜Q13 | 帳票照合、バックアップから復元、iPhone実機確認、権限別受入 |

給与額と処分金額は、条件が未確定の段階で仮計算を本番機能にしない。既存ソフトに計算を任せる選択肢もQ08で決める。

## 4. 変更の進め方

1. 対象となる要件IDと要確認IDを決める。必要な回答を `open-questions.md` に記録する。
2. 作業用ブランチで小さく実装し、データ項目・画面説明も更新する。
3. 金額や個人情報を含まないテストで、入力・計算・修正・権限の期待値を確認する。
4. `npm test`、`npm run check`、変更画面の表示確認を行う。
5. 差分を確認し、機密データや環境変数を含めずにコミット／レビューする。

初回は空リポジトリへこの土台を配置する。以後の開発課題は上表や要確認IDを単位に切り出せる。自動デプロイ、外部サービス課金、ライセンス付与は今回の構成に含めない。
