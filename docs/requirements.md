# 要件整理

作成日：2026-11-03（日本時間）。ユーザーの今回の依頼と、この会話で共有済みの運用方針を根拠とする。既存の社内台帳、給与規定、実ファイルは未確認。

## 目的と利用者

従業員がiPhoneで日報を入力し、事務側が同じ内容を各台帳へ再入力する負担を減らす。管理側はPCで確認・集計する。

| 区分 | 方向性 | 未確定部分 |
| --- | --- | --- |
| 一般社員 | 自分の作業・勤務・運搬・給油を日報へ入力 | 提出後の編集範囲、他人分の代理入力 |
| 監督 | 担当現場の日報確認 | 承認権限、閲覧できる社員・現場の範囲 |
| 管理者／事務 | マスタ・単価・締め・台帳管理 | 給与閲覧者、権限付与者、役割を兼ねる条件 |

社員番号は識別に使う方針。社員番号だけを認証の秘密にはしない。認証方式・権限境界はQ01・Q02で確認する。

## 共有済みの方向性

- 日報を共通の入力元にし、出勤簿・給与・運行管理・処分費・燃料管理へつなぐ。
- 従業員の主な入力は日付、氏名／社員、現場、作業内容、出勤・退社、休憩。
- 運搬は出発地・運搬先・材種・数量／単位・車両／車種・運転手を記録する。
- 給油は車両／重機と給油量（L）を記録する。
- 残業の入力欄は日報に置かず、確定した勤怠ルールに基づき管理側で算出する。
- 材料費・処分費などの金額／単価は管理側で設定する。
- 不明な項目を0や推測値に置き換えず「要確認」にする。

## 初期試作の機能と受入条件

| ID | 要件 | 今回の受入条件 |
| --- | --- | --- |
| R01 | 日報入力 | 必須項目・時刻・数量の不正を止め、入力値を失わず修正できる |
| R02 | 台帳連動 | 1回の反映で対象5画面に同じ日報から反映される |
| R03 | 修正 | 同一IDの日報更新で置き換え再集計し、古い値と重複加算しない |
| R04 | 勤務資料 | 同日内の参考実働を分で算出。給与額や残業は未確定と明示 |
| R05 | 運搬・処分 | 複数明細に対応し、m³・t・台を別の数量として保持・集計 |
| R06 | 燃料 | 複数の車両／重機の給油を記録し、車両／重機ごとに集計 |
| R07 | 期間 | 月で集計対象を絞れる。空欄では全期間を表示 |
| R08 | 操作環境 | iPhone相当の幅で入力でき、長い表は横スクロールできる |
| R09 | 試作の限界 | メモリのみ・架空データ用・金額未確定を画面とREADMEに表示 |

## 試作の操作上の仮制約

以下は社内ルールの決定ではない。本番採用の可否はQ05・Q06で確認する。

- 1日報＝1社員・1現場・同日内の1勤務区間。複数現場は時間を分けた別日報で試す。
- 勤務区間が重なる同一社員の日報は、二重加算を避けるため反映を止める。
- 日またぎ、休暇、欠勤、実働0分、休憩の個別区間、移動時間の配分には未対応。
- 出勤日数は社員・月ごとの作業日の重複を除いた数であり、賃金計算上の出勤日数ではない。
- 運搬先の仮マスタは処分場のみ。一般配送や現場間移動、空車移動は後続で扱う。
- 全6画面を操作できるが、役割別のアクセス制御はない。閲覧範囲の実装済みとは扱わない。

## 後続の実用版

認証と権限、共有保存、日報の提出／確認／差戻し、変更履歴、締め処理を先に整える。続いて、承認済み勤怠からの給与資料、単価付き処分費、出力機能を実装する。具体的な状態遷移と計算規則は回答後に設計する。
